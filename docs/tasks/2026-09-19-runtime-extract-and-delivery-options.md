## 1. Problem restatement

Task #20 as written is a **file move**: `.cursor/agents|skills|rules` → `workflow-runtime/`, flip `RUNTIME_ROOT`, add a Cursor linker. That is still correct, but it is narrower than what is actually wanted.

The wider intuition, restated:

| # | Want | Today |
| - | ---- | ----- |
| 1 | Canonical workflow source is host-neutral | `.cursor/` is canonical; Claude symlinks into it (pre-extract Claude installer) |
| 2 | CI performs the host adaptations automatically | Adaptation was a manual local Claude install step; [`install.py`](../../install.py) linked nothing at all |
| 3 | Git tail gated by CI, PR-shaped | `sheep-sync` pushes the feature branch, `sheep-integrate` merges to `main` locally and pushes; [`smoke.yml`](../../.github/workflows/smoke.yml) runs on `push: main` — **after** the merge, never before |
| 4 | Local dogfood still works | Dogfood is the only real end-to-end proof there is |

Three of these are different projects wearing one hat. The analysis below splits them and sequences them.

**The headline judgement:** #20 is not competing with the template/CI ambition — it is a **hard prerequisite** for it. There is nothing host-neutral to adapt *from* until the move lands. Any CI adapter job built today would have to read `.cursor/` as its input, which cements exactly the landlord relationship #20 exists to remove. So: **#20 first, unconditionally.** The template work is a separate project, and it does not block the Shinobu fork at all — Shinobu arrives by `git clone`, not by instantiating a template.

## 2. Layer map

| Layer | Decision | Blocks the fork? |
| ----- | -------- | ---------------- |
| **A** | Canonical runtime extract in this repo (`workflow-runtime/` + host adapters) | **Yes** — must land before the tag |
| **B** | Distribution: `nicki_template`, release artifact, or extended installer | **No** — Shinobu is a fork, not a consumer |
| **C** | Validation surface: what CI can prove vs what only a human can | No — but C is what makes D honest |
| **D** | Git tail: local merge vs PR-gated integrate | **Decision point** — cheap enough to land pre-fork; see §4 |
| **E** | Fork timing and the stop line | — |

A and B are frequently conflated because both say "install". They are not the same: **A produces the canonical tree and the local adapters; B moves that tree to someone else's machine.** This repo has, today, no consumer who is not its author.

## 3. Options per layer

### Layer A — canonical runtime extract

#### A.1 What moves

Mechanical and already specified by [the B checklist](host-runtime-backlog-and-approach-b.md). Current surface: 13 flat agents in `.cursor/agents/`, 21 skill folders in `.cursor/skills/`, one rule in `.cursor/rules/`.

Good news from inspection: [`bootstrap_utils.py:11`](../../.cursor/skills/nicki/scripts/bootstrap_utils.py#L11) resolves `routing.json` as `SCRIPT_DIR.parent / "routing.json"` — script-relative, so it survives the move untouched. The `link_dir` / `RUNTIME_ROOT` / `generate_claude_md()` machinery Approach A shipped is directly reusable.

#### A.2 Canonical vs generated — the actual table

This answers "what exactly should be canonical vs generated" precisely, because the current checklist leaves several rows implicit.

| Thing | Canonical | Generated by | Notes |
| ----- | --------- | ------------ | ----- |
| Agents | `workflow-runtime/agents/*.md` (flat) | `.cursor/agents`, `.claude/agents` — directory links | Filename ↔ frontmatter `name:` must match |
| Skills | `workflow-runtime/skills/<name>/SKILL.md` | `.cursor/skills`, `.claude/skills` — directory links | Exactly one level; Claude discovers no deeper |
| Routing | `workflow-runtime/skills/nicki/routing.json` | — | Canonical, never generated |
| Invocation rule | `workflow-runtime/rules/nicki-default.md` — **body only, no host frontmatter** | `.cursor/rules/nicki-default.mdc` (Cursor frontmatter prepended), `CLAUDE.md` (host-term substitutions) | See A.3 |
| Cursor hooks | `.cursor/hooks.json`, `.cursor/hooks/` | — | Canonical **and** host-specific. No neutral twin. Claude gets no parity. |
| Cursor permissions | `.cursor/permissions.json` | — | Same: canonical where it sits |
| Claude permissions | **nothing** | — | `.claude/settings.json` exists on disk, is gitignored, tracked count is zero, and no installer writes it. Unmanaged surface — record, do not fix in #20. |
| Path strings in sheep bodies | `workflow-runtime/skills/...` after A.5 | — | See A.4 — split by reader |
| Machine-read paths (smokes, routing `harness_failure.scripts`, permissions allowlist, worktree marker) | `workflow-runtime/...` | — | Must flip **in the move commit** |

#### A.3 The rule file should stop being an `.mdc`

Today `nicki-default.mdc` carries Cursor frontmatter (`description:`, `alwaysApply:`) and `generate_claude_md()` / `render_claude_md()` strips it, then applies host vocabulary swaps — `Task (subagent_type: nicki)` → Agent tool, `AskQuestion` → `AskUserQuestion`, and so on (now in `install_common.py`).

That substitution table is the right idea and the wrong location. Moving an `.mdc` with Cursor frontmatter into `workflow-runtime/rules/` is host-neutral in name only. Make the canonical rule plain Markdown with **neutral placeholders**, and give each installer a small declared substitution map. Both adapters then generate symmetrically instead of Claude being a patch on top of Cursor.

Small, contained, and it removes the last "Cursor is the source" artifact.

#### A.4 Path prose — one decision is wrong, split it by reader

The checklist offers "compatibility first" vs "rewrite later" as a single global choice. It is two populations with opposite answers.

| Population | Count | Reader | Verdict |
| ---------- | ----- | ------ | ------- |
| **Machine-read** — `tests/smoke/*.py` asserts, [`routing.json:111,123`](../../.cursor/skills/nicki/routing.json#L111), [`permissions.json`](../../.cursor/permissions.json) allowlist, [`create-worktree.py:176`](../../.cursor/skills/start-task/scripts/create-worktree.py#L176) workspace marker | ~25 strings | Python / the host's allowlist matcher | **Flip in the move commit. Non-negotiable.** |
| **Prose in agent and skill bodies** — `Run .cursor/skills/<x>/SKILL.md` | ~40 strings across 13 agents + skills | The model, resolving against workspace root | Resolves fine through the `.cursor/` link. Flip in a follow-up sed, for the fork's sake. |

Why the machine population cannot wait: [`tests/smoke/git_tail.py`](../../tests/smoke/git_tail.py) asserts `.cursor/agents/sheep-sync.md` **exists**. After the move that path is a link, and whether it exists in CI depends entirely on A.6. Leaving those asserts on `.cursor/` means the smoke suite is testing the adapter while claiming to test the runtime. Flip them.

The prose population is a genuine `sed` and should land before the tag anyway: `.cursor/` inside sheep bodies is precisely the "hidden fork coupling" [`OWNERSHIP.md`](../OWNERSHIP.md) names. It is just not *correctness*-blocking.

#### A.5 The unknown that gates the whole slice

Approach A proved **Claude** follows a symlinked `.claude/agents` → `.cursor/agents`. It is live on disk right now and it works.

It has **not** been proven that **Cursor** follows a symlinked `.cursor/agents` → `../workflow-runtime/agents`. That is the untested half, and the entire A design rests on it.

Spike it manually before touching anything — make the two links by hand, restart Cursor, confirm the agent list and a skill invocation. Two minutes.

If Cursor refuses: A still lands, but `install.py` **copies** into `.cursor/` instead of linking, and the Cursor edit loop becomes edit-canonical-then-reinstall (the same degraded path Windows already has). Host-neutral either way; worse DX. Know which world you are in before writing the installer.

#### A.6 Track 1 vs Track 2 — the choice that decides three other problems

| | **Track 1 — commit the Cursor links** | **Track 2 — generate and gitignore** |
| --- | --- | --- |
| `.cursor/agents`, `.cursor/skills` | Committed symlinks (git mode `120000`) | Untracked, created by `install.py` |
| New worktree | Works immediately — checkout materializes the links | **Broken** until something links inside the new worktree |
| CI checkout | Works immediately | Must run `install.py` before `test.py` |
| `install.py`'s job | Verify and self-repair | Create, then verify |
| Windows | Checkout without `core.symlinks=true` yields text files containing the target path — silently wrong until `install.py` detects and copies | Copy fallback on first install, as today |
| `.claude/` | Stays generated + gitignored either way | Same |

**Recommend Track 1.** It deletes two whole failure classes for the price of one already-documented degradation. The worktree class is the sharp one: [`OWNERSHIP.md`](../OWNERSHIP.md)'s migration table already flags "worktrees inheriting `.cursor/`", and under Track 2 every `sheep-start` would have to grow a link step inside the new worktree — a load-bearing change to [`create-worktree.py`](../../.cursor/skills/start-task/scripts/create-worktree.py) that is easy to forget and fails silently (Cursor simply shows no agents). Track 1 makes it a non-event.

Cost of Track 1: `_same_link()` in `install_common.py` must also recognise "this is a regular file whose contents look like my target" — the Windows-checkout case — and repair it.

### Layer B — distribution and the `nicki_template` ambition

First, name the consumers honestly, because the option set collapses once you do:

| Consumer | How it gets the runtime today | Does a template help? |
| -------- | ----------------------------- | --------------------- |
| This repo (dogfood) | It *is* the source | No |
| `projects/tetris-clone-frp` | A stale hand-copy: `.cursor/skills/` only, **no `.cursor/agents/`** | Yes — this is the real pain |
| `projects/castlemill-landing`, `projects/project-jung` | No `.cursor/` at all | Yes |
| **Shinobu** | `git clone` of a tag, full history | **No** — a fork is not a template instantiation |

So: the template ambition is about **managed projects**, not about Shinobu, and not about this repo. That fact alone removes it from the fork's critical path.

| Option | Shape | Trade-off |
| ------ | ----- | --------- |
| **B0 — extend the installer** | `python3 install.py --project projects/<name>` links or copies `workflow-runtime/` into that project's `.cursor/` and `.claude/` | Reuses `link_dir`. Hours, not days. Fixes the actual observed staleness. No CI, no second repo, no token. **The YAGNI answer.** |
| **B1 — same-repo generated commit** | CI on push to `main` materializes `.cursor/`, `.claude/`, `CLAUDE.md` and commits back | **Reject.** Creates a push→CI→push loop that collides with the git tail: `sheep-integrate` pushes `main`, CI lands a commit on top, and the next `sheep-sync` merges a commit no human wrote. Also reverses the `.gitignore` decision for `.claude/` and `CLAUDE.md`, and needs a bot token with write access to `main`. The cure is worse. |
| **B2 — release artifact on tag** | CI on `v*` builds `nicki-runtime-<version>.tar.gz` containing `workflow-runtime/` plus **materialized** (copied, not linked) `.cursor/`, `.claude/`, `CLAUDE.md`; attaches to a GitHub Release | The right *shape* of the ambition. No commit loop. Windows-safe by construction. Version pinning falls out and [`nicki_version.yaml`](../../nicki_version.yaml) finally means something. ~40 lines of workflow YAML. Consumers get copies, so runtime edits need re-install — already the documented fallback behaviour. |
| **B3 — separate `nicki_template` repo** | Push here → Action opens a PR of regenerated adapters in a template repo; consumers instantiate it | Literally what was described, and premature. Two repos to keep in sync before there is a consumer who is not the author; a cross-repo PAT; and it muddies the fork story — a *template* repo and a *fork* repo are different things and will be confused. |
| **B4 — submodule / subtree** | Consumers vendor `workflow-runtime/` as a submodule | **Reject on principle.** Reintroduces a live shared runtime across repos, contradicting the settled "no shared runtime package." |

**Recommendation: B0 if the managed-project staleness is actually biting; B2 when the first non-author consumer appears; B3 only after B2 proves insufficient.** None of it before the fork.

#### Can CI verify adapters without Cursor or Claude binaries?

Partly, and it is worth being exact about the line, because "CI generates the adapters" tempts one into believing CI *validated* them.

**CI can prove, cheaply and today:**

- Every agent file's frontmatter `name:` equals its filename stem.
- Every skill is exactly `<skills>/<name>/SKILL.md` — one level, no deeper (the rule Claude actually enforces).
- Every host link resolves to a real directory under `workflow-runtime/`.
- `CLAUDE.md` and `.cursor/rules/nicki-default.mdc` regenerate **byte-identically** from the canonical rule — a drift check that catches hand-edits of generated files.
- Every path string in agents, skills, `routing.json`, and the permissions allowlist points at a file that exists.
- Routing graph: every `steps.<x>.sheep` names an agent file that exists; `default_next_step` chains terminate at `done`.
- Installers are idempotent and self-repairing: run twice, delete a link, run again, assert.

**CI cannot prove, at any price:** that Cursor lists the agent; that Claude offers the skill; that a `preToolUse` hook fires; that `subagent_type: sheep-spec` spawns anything. There is no headless Cursor or Claude binary to run in Actions.

The honest substitute is a **discovery-contract test** asserting the layout rules each host documents. It catches the failure that actually bites — a skill nested two deep, an agent whose `name:` drifted from its filename — without pretending to be an integration test.

The conclusion to hold onto: **CI is a structural gate, never a behavioural one.** Running Nicki on Nicki is the end-to-end suite and will remain so. Design D with that in mind — a green check means "the shape is intact", not "it works".

### Layer D — git tail

Current tail, from [`routing.json`](../../.cursor/skills/nicki/routing.json) and [`NICKI.md:214`](../NICKI.md#L214):

```
sync → archive → sync → integrate → close
```

`sheep-sync` commits, merges `main` into the feature branch, pushes the feature branch ([`sync-task/SKILL.md`](../../.cursor/skills/sync-task/SKILL.md)). `sheep-integrate` merges the feature branch into `main` **in a separate target worktree** and pushes `main` ([`integrate-task/SKILL.md`](../../.cursor/skills/integrate-task/SKILL.md)).

Two structural facts that shape every option:

1. **The feature branch is already pushed.** A PR can already exist; nothing opens one and nothing waits for it.
2. **Conflicts already surface during `sync`**, in the local merge of `main` into the feature branch, with the human present. That is the right place and it does not move.

| | **D0 — keep as is** | **D1 — sync opens the PR, integrate merges when green** | **D2 — full PR-native** | **D3 — local gate only** |
| --- | --- | --- | --- | --- |
| Change | none | `sync` adds `gh pr create --fill`; `integrate` waits on `gh pr checks` then merges | + branch protection on `main`, required checks, no direct pushes | `integrate` refuses unless `python3 test.py` passes in the feature worktree |
| **Conflict UX** | Local, human-approved | **Unchanged** — still local, during `sync`. GitHub's web conflict UI never appears. | Unchanged | Unchanged |
| **Worktree model** | Unchanged | *Simpler* — `gh pr merge` needs no target worktree, so the "target branch worktree" input disappears. But `close` must then `git -C <main> pull`, or local `main` silently drifts behind. | As D1 | Unchanged |
| Speed | fastest | + one CI wait per task (~30s for this suite) | + same | + local suite runtime |
| **What breaks in the sheep** | — | [`integrate-task/SKILL.md`](../../.cursor/skills/integrate-task/SKILL.md) procedure steps 1–4 rewritten; [`sheep-integrate.md`](../../.cursor/agents/sheep-integrate.md) prose; `gh` entries added to [`permissions.json`](../../.cursor/permissions.json) and `.claude/settings.local.json`. `sync-task` gains one line. `routing.json` unchanged. `git_tail.py` unaffected — it asserts files and routing, not verbs. | As D1, plus branch protection blocks *you*: the last five commits went straight to `main`. | `integrate-task` gains a precondition |
| Migration cost | 0 | **Small — one skill, one agent, one allowlist** | Medium, and it changes daily habits | Tiny |
| New failure mode | `main` can receive an unverified merge; `smoke.yml` finds out **after** | Hard dependency on `gh` + GitHub; must degrade gracefully where there is no remote | Same + protection friction | None; but proves nothing about the merge result |

**Recommend D1.** It closes the actual gap — the gate is retrospective today — for a genuinely small diff, and it leaves the two things that matter most alone: conflict resolution stays local and human-approved, and the consent model does not change (see §Q6 below). Add one paragraph to `integrate-task` for graceful degradation: no remote, or no `gh`, → fall back to the current local merge and say so in `summary`.

D2 is the right end state and premature: branch protection hardens a repo that has one contributor. D3 proves the feature branch was green, not the merge result, which is the wrong half.

## 4. Recommendation

**One path: finish #20 as the next slice, with the two corrections above — flip machine-read paths in the move commit, and commit the Cursor links rather than generating them. Then decide D1. Then tag and fork. Leave Layer B entirely alone until a non-author consumer exists.**

Why this one:

- **It is the only ordering that works.** Template/CI adaptation has no host-neutral input until A lands. Building B first means building an adapter whose source is `.cursor/`.
- **It is the only slice the fork actually requires.** Everything else in this note is additive and can be adopted independently by either repo afterwards.
- **It is reversible.** A move plus a `RUNTIME_ROOT` constant plus committed symlinks is a `git revert`. A template repo and a cross-repo sync Action are not.
- **It fixes the real complaint about CI.** The gap is not "no automated adaptation" — local adaptation is one script and works. The gap is that `smoke.yml` runs **after** the merge to `main`. D1 fixes that with one skill edit. The template project fixes nothing that currently hurts.

Explicitly: **the `nicki_template` / CI-adaptation ambition is a separate project from #20.** It is a good project. It has one honest consumer today (three managed clones, one of them half-installed), zero external users, and no bearing on Shinobu. Treat it as B0 now and B2 later, not as a precondition for anything.

## 5. Minimal first slice (YAGNI)

**Slice A1 — the extract.** One PR. Concrete, in order:

**Step 0 — spike (before any file moves).** By hand: `ln -s ../workflow-runtime/agents .cursor/agents`, restart Cursor, confirm the agent list and one skill invocation. Outcome decides link-vs-copy for Cursor.

**Moves**

1. `git mv .cursor/agents workflow-runtime/agents`
2. `git mv .cursor/skills workflow-runtime/skills`
3. `git mv .cursor/rules/nicki-default.mdc workflow-runtime/rules/nicki-default.md` — strip the Cursor frontmatter into the generator

**Installers**

6. [`install.py`](../../install.py): add `verify_cursor_runtime()` (repair the committed links; copy-fallback where the OS refuses) and `write_cursor_rule()` generating `.cursor/rules/nicki-default.mdc` with frontmatter.

**Machine-read path flips — same commit, no exceptions**

7. `tests/smoke/`: `git_tail.py` `REQUIRED`, `harness_failure.py`, `errors_append.py`, `archive_side_effects.py`, `status_update.py`, `status_vocabulary.py`, `routing_write.py`, `bootstrap_contract.py`. Leave `agent_tools.py` on `.cursor/hooks/…` — hooks stay Cursor-canonical.

9. [`create-worktree.py:176`](../../.cursor/skills/start-task/scripts/create-worktree.py#L176) — add `workflow-runtime/` to the workspace-root marker tuple; keep `.cursor/skills/start-task` for one release.
10. [`permissions.json`](../../.cursor/permissions.json) — the six `python3 .cursor/skills/…` and `bash .cursor/skills/…` allowlist prefixes.

**Git tracking**

11. `.gitignore`: keep `.claude/` and `CLAUDE.md` ignored. Add `.cursor/rules/nicki-default.mdc` (generated). Commit `.cursor/agents` and `.cursor/skills` **as symlinks**.

**CI**

12. [`smoke.yml`](../../.github/workflows/smoke.yml): insert `python3 install.py` before `python3 test.py`. This is the only automated proof that the adapter step runs at all, and it costs one line.

**Docs**

13. [`README.md`](../../README.md) — 18 `.cursor/` references, including the Layout tree and the atomic-save warning, which must now name both host trees. Also fix the stale `docs/future-tasks/PLAN.md` and `docs/tasks.md` links while in there.

## 7. Risks and migration pitfalls

| Risk | Where it bites | Mitigation |
| ---- | -------------- | ---------- |
| **Cursor will not follow a symlinked `.cursor/agents`** | Kills the link design; A becomes copy-based | Spike first (§5 Step 0). Fallback is copy-on-install — worse DX, still neutral. |
| **Worktrees inherit an unlinked tree** | Under Track 2, every new worktree has `workflow-runtime/` but no `.cursor/agents` → **Cursor silently shows no agents** | Track 1 (commit the links) makes this a non-event. This is the single strongest argument for Track 1. |
| **Smokes assert through the adapter** | `git_tail.py` and friends "pass" because a link happens to exist, proving nothing about the runtime | Flip machine-read paths in the move commit — step 7 |
| **Atomic saves sever links** | Editors that write-temp-then-rename replace `.cursor/agents` with a regular directory | Already documented for `.claude/`; now applies to **both** trees. Installers self-repair. README must say so. |
| **Windows symlink checkout** | Track 1 yields text files containing the link target — silently wrong | `_same_link()` detects and copy-repairs; `install.py` warns that re-runs are needed after edits |
| **Half-flipped paths** | Prose says `workflow-runtime/`, the allowlist still says `.cursor/` → permission denials mid-pipeline | Permissions and prose flip in the same commit as the code that uses them |
| **B1's push loop** | CI commits on `main` after `sheep-integrate` pushes; next `sheep-sync` merges an unauthored commit | Reject B1. Use B2 (tag-triggered artifact), which never writes to a branch. |
| **`gh` as a hard dependency** | D1 breaks on a project with no GitHub remote | Degrade to the current local merge and say so in `summary` |
| **`close` on a stale local `main`** | Under D1, `gh pr merge` lands remotely; local `main` is behind when `close` runs | `close-task` pulls `main` before teardown |
| **Empty leftover `.cursor/skills/archive-task/`** | Untracked empty dir shadowing the real `task-archive/` | Delete during the move |

Real forks only. Nothing settled in [`OWNERSHIP.md`](../OWNERSHIP.md) or [`SHINOBU_NEXT_STEPS.md`](../SHINOBU_NEXT_STEPS.md) is reopened here.

1. **Track 1 or Track 2?** Committing the Cursor symlinks removes the worktree and CI failure classes at the cost of a degraded Windows checkout. Is Windows a real target, or a documented-degraded path? *(Recommendation: Track 1.)*
2. **D1 before or after the fork tag?** Before means both products inherit a green gate for free; after means the fork happens sooner and each repo adopts independently. Depends on whether the tail edit fits in one sitting. *(Recommendation: before — it is one skill, one agent, one allowlist.)*
3. **Is managed-project staleness actually hurting?** `projects/tetris-clone-frp/.cursor/` has `skills/` and no `agents/`; the other two have no `.cursor/` at all. If Nicki-on-Nicki is the only live dogfood, B0 is worth nothing and should not be built.
4. **Is `gh` acceptable as a git-tail dependency?** D1 binds the tail to GitHub. The alternative is a generic "some check passed" contract that costs more and buys portability nobody is using yet.
